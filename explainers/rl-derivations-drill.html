1. On-Policy vs Off-Policy, and πold vs πref

On-policy: the gradient is estimated from data sampled by the current policy. Off-policy: data comes from a different (older or other) policy.

PPO is "approximately on-policy." It takes multiple gradient epochs over a batch sampled from πold, correcting for drift with the importance-sampling ratio:

rt(θ) = πθ(at|st) / πold(at|st)

This ratio is clipped to [1−ε, 1+ε]. πold is refreshed every rollout iteration.

The distinction people fumble: πold and πref are different objects with different roles and different update cadences. Toggle the cards below to compare them side by side.
πold

Importance-Sampling Anchor

Role: The policy that generated the current batch of data. Used to compute the probability ratio rt(θ) for the clipped surrogate objective.

Updated: Every rollout boundary — snaps to πθ at the start of each new data-collection phase.

Lives in: PPO, GRPO, any algorithm using IS correction.

πref

KL-Penalty Anchor

Role: The frozen SFT checkpoint. Used as the reference distribution in the KL-divergence penalty DKL(πθ ‖ πref) that prevents the policy from drifting too far from the initial well-behaved model.

Updated: Never — frozen for the entire training run.

Lives in: RLHF / DPO — anywhere KL regularisation is used.

2. The Policy Gradient Theorem (Full Derivation)

Step through one algebraic move at a time. The highlighted line is the current move.

Worked example: 2-armed bandit

Policy: π(a1) = 0.7, π(a2) = 0.3. Rewards: r(a1) = 1, r(a2) = 5.

Expected return: J = 0.7 × 1 + 0.3 × 5 = 2.2

The policy gradient for each arm (using softmax parameterisation so ∇ log π(ai) = 1 − π(ai) for the chosen arm):

Arm 1: π(a1) × ∇ log π(a1) × r(a1)   = 0.7 × (1 − 0.7) × 1 = 0.7 × 0.3 × 1 = +0.21 Arm 2: π(a2) × ∇ log π(a2) × r(a2)   = 0.3 × (1 − 0.3) × 5 = 0.3 × 0.7 × 5 = +1.05

The gradient signal for arm 2 is 5× larger despite being chosen less often. The high-reward, low-probability arm gets pushed up — exactly what we want. The gradient naturally amplifies underexplored, high-reward actions.

3. Baselines and the 3-Line Unbiasedness Proof

A baseline b(s) is any function of state only subtracted from the return:

∇J = E[Σt ∇ log π(at|st) (R − b(st))]

Purpose: variance reduction. Hard requirement: b must not depend on the action.

The proof (3 lines, each expandable)

We want to show: Ea~π[∇θ log πθ(a|s) · b(s)] = 0

Line 1: b(s) Σa πθ(a|s) ∇θ log πθ(a|s)

b(s) doesn't depend on a, so it pulls out of the expectation / weighted sum over actions.

Line 2: = b(s) Σa ∇θ πθ(a|s)

Log-derivative trick in reverse: π ∇ log π = π · (∇π/π) = ∇π.

Line 3: = b(s) ∇θ Σa πθ(a|s) = b(s) ∇θ 1 = 0

Probabilities sum to 1. The gradient of a constant is 0. QED.

GRPO connection: GRPO’s group-mean reward baseline is valid because it’s computed from other rollouts for the same prompt, not from the current action’s identity. An action-dependent "baseline" would corrupt the gradient.

4. TD Residual and GAE (λ Slider)

TD Residual

δt = rt + γ V(st+1) − V(st)
Common error: dropping the γ from δt. The discount factor multiplies V(st+1), not just the return. Without it the residual overweights future value.

Generalised Advantage Estimation

ÂtGAE(γ,λ) = Σl=0∞ (γλ)l · δt+l

This is a discounted sum over future residuals — not a moving average of past ones (common misconception).

  • λ = 0 → Ât = δt (single one-step TD residual). Trusts the critic: low variance, high bias.
  • λ = 1 → Ât = Σl γl δt+l, which telescopes to (Σl γl rt+l) − V(st) — the Monte-Carlo return minus baseline. Unbiased, high variance.
Telescoping proof (λ = 1 reduces to MC)
Ât = Σl=0T−t γl δt+l = Σl=0T−t γl [rt+l + γV(st+l+1) − V(st+l)] = Σl γl rt+l + Σl γl+1V(st+l+1) − Σl γlV(st+l) The two V sums telescope: most terms cancel pairwise. = Σl γl rt+l + γT−t+1V(sT+1) − V(st) With V(sterminal) = 0: = (Σl γl rt+l) − V(st) = Gt − V(st)

5. PPO’s Clipped Objective

LCLIP(θ) = Et[ min( rt(θ) Ât, clip(rt(θ), 1−ε, 1+ε) Ât ) ]

Toggle between Â > 0 and Â < 0 to see how the objective shapes the gradient.

Â > 0 (good action): The objective increases linearly in r until r = 1 + ε, then flattens. No incentive to push r above the clip — the policy has moved far enough from πold.

6. DPO’s Closed-Form Trick (Stepper)

Step through the derivation that eliminates the reward model entirely.

Why offline DPO underperforms online RL on reasoning / agentic tasks
1

Stale, off-distribution data

The preference pairs were generated by a different policy. As the current policy improves, those pairs become increasingly irrelevant — distributional mismatch grows with every gradient step.

2

No exploration

DPO can only reweight existing completions. It cannot discover new reasoning chains, new tool-use patterns, or novel solutions. Online RL generates fresh data from the current policy each iteration.

3

Verifiable rewards remove offline’s cost advantage

Where rewards are verifiable (math, code, task completion), online RL gets cheap, unhackable signal. The main reason to go offline — avoiding expensive human preference collection — disappears.

7. What Changes in Multi-Turn Agentic RL

Four reasons multi-turn is fundamentally harder. Non-deterministic transitions come first because they break the simplifying assumption that makes single-turn RL tractable.

1

Non-deterministic transitions

The environment responds, and the policy doesn’t control what comes back. In single-turn, the "transition" is just your own token appended — deterministic.

2

Variable / unbounded episodes

Termination must be designed: final-answer flag OR turn/token cap. Heterogeneous episode lengths create batching pain.

3

Sparse terminal reward

One scalar reward explains 15 decisions. In GRPO, every token inherits the same sequence-level advantage — credit assignment is extremely coarse.

4

Per-rollout isolation

One sandbox/browser per rollout. With G=16, that’s 16 environments per prompt. GRPO-specific: group advantage compares G rollouts of the same prompt — only fair if all G start from an identical environment state. Leakage corrupts the baseline itself.

Single-turn vs multi-turn comparison

DimensionSingle-turn (RLHF/RLVR)Multi-turn (Agentic RL)
StateToken context (growing sequence)LLM context + external env state
ActionNext tokenText output OR tool call
TransitionDeterministic (append token)Non-deterministic (env responds)
RewardTerminal (end of completion)Terminal and/or intermediate
Episode lengthHundreds of tokensPotentially unbounded
IsolationNot neededCritical (containerised per rollout)

Token masking

Mask from the loss: system prompt, user messages, tool outputs. They stay in context but contribute zero gradient.

Why: per-token loss = log π(token) × advantage. Tool-output tokens weren’t chosen by the policy. Gradients on them assign credit for non-actions and destabilise training. (Search-R1’s retrieved-token masking ablation confirmed this.)

"Masked from loss ≠ removed from context."

8. Environment & Reward Design Reflexes

Quick checklist

  • Termination: final-answer flag OR max-turns/token cap — never flag-only (the agent can loop forever).
  • Verifiable reward first: exact match, test suite, environment-state check. LLM-judge is a last resort and every judge is a hacking surface.
  • Never train against a live/mutable environment. Non-deterministic + non-resettable = unreproducible. Use a snapshot corpus or staging copy with reset (the Search-R1 pattern).
  • Resettability to identical start state is what makes GRPO group advantages comparable. Without it, variance in initial conditions corrupts the baseline.
  • Isolation: one sandbox per rollout. No shared state across rollouts within a group.
  • Reward shaping bias: intermediate bonuses are a hacking surface. Prefer outcome-only; add shape only when the outcome signal is too sparse to learn from.
