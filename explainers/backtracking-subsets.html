The backtracking template

Added 2026-08-27 · choose → explore → un-choose

One template runs the whole backtracking family — subsets, permutations, combination sum, word search, N-Queens. It looks alien at first because it works in a way that feels upside-down. This page makes it move.

The one idea: a walker photographing its position

A "combine the answers" solution returns a finished list from each call and glues them together — values flow up. Backtracking is the opposite:

There is one partial answer being built, called path. A single walker walks down a decision tree. At every node it stands on, it takes a photograph of path and drops the photo into result. Nothing flows up. result fills as a side effect of walking.

Think of path as a whiteboard showing your current selection. You write an item, go explore everything built on top of it, then erase it to try the next item. That erase is the move everyone misses.

def backtrack(start, path):
    result.append(path[:])        # PHOTO   — snapshot current subset
    for i in range(start, len(nums)):
        path.append(nums[i])      # CHOOSE  — include nums[i]
        backtrack(i + 1, path)    # EXPLORE — build on top of it
        path.pop()                # UNDO    — erase, try next
    return

Why the pop() is non-negotiable

The whiteboard is shared across every branch. After you finish exploring "what if I include nums[i]?", you must erase it — otherwise the next branch starts on a dirty whiteboard and builds garbage. See it for yourself:

Why backtrack(i + 1, …) and not i?

The start index says "only look at elements to the right of where I am." That is what stops you generating both [1,2] and [2,1] — for subsets, order doesn't matter, so you fix one direction. Small changes to this one line retarget the whole template:

The bridge from your divide-and-conquer brain

If "mutate then undo" feels wrong, here's the same tree walk in an immutable style — a fresh list per branch, so there's nothing to erase:

def backtrack(start, path):
    result.append(path)                    # no [:] needed — path is already fresh
    for i in range(start, len(nums)):
        backtrack(i + 1, path + [nums[i]]) # brand-new list each branch

Correct, and closer to how you already think. So why is append/pop the one to memorize? Because "undo my last move" generalizes and "copy everything" doesn't:

  • Word Search (#79): mark a grid cell visited → explore → un-mark it. You can't cheaply copy the whole grid per branch.
  • N-Queens: place a queen → explore → remove it.
  • It's O(n) working memory (one shared path), not a copy at every branch.

The append → recurse → pop rhythm is the single motion that carries across the entire family. That's why it's the template.
