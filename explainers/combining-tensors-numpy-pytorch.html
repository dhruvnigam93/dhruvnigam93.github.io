Combining tensors: concat vs stack

Added 2026-08-26 · NumPy & PyTorch · the axis question, visually

Every "combine these arrays" question is really one question: am I growing an axis that already exists, or inventing a new one? Get that right and the API name falls out. Get it wrong and you spend ten minutes fighting shapes. This page is the visual answer, with the NumPy ↔ PyTorch commands side by side.

The whole idea in two rules

concat / cat — join along an axis that already exists. Rank stays the same. Inputs must match on every axis except the join axis. The join axis length becomes the sum.

stack — lay the inputs into a brand-new axis. Rank goes up by 1. Inputs must have the exact same shape. The new axis length = how many tensors you passed.

1 · concat vs stack (the core toggle)

Two 1-D arrays, a = [1,2,3] and b = [4,5,6], each shape (3,). Same inputs, two very different results:

b  (3,)
result  

See it? concat glued them end-to-end — still 1-D, just longer. stack made each array a row of a new 2-D array. Same data, different rank.

2 · Which axis? (the axis / dim knob)

Once you're joining along an existing axis, you pick which one. Here A and B are both (2,2). Toggle the axis:

Named shortcuts for the two common cases (so you don't have to remember which number the axis is):
  • vstack = concat along axis 0 (stack rows on top of each other → taller).
  • hstack = concat along axis 1 for 2-D (place side by side → wider).

3 · Adding a new axis (unsqueeze / expand_dims)

Not combining two tensors — reshaping one so its rank fits (for broadcasting, matmul, batching). A vector v = [1,2,3], shape (3,). Where does the new size-1 axis go?

shape  

The data never changes — only the rank. The dashed box is the new outer axis. (1,3) is a row vector, (3,1) a column vector. This is exactly the trick for turning (N,) into something you can broadcast or matmul.

The reverse: squeeze drops size-1 axes. (8,1,1) → squeeze → (8,). Pass an axis to be surgical: squeeze(1) removes only axis 1. Great for cleaning up after a matmul or a keepdim reduction.

Same operation, the two dialects. The big rename: NumPy says axis, PyTorch says dim.

The ⚠ naming trap

tensor.repeat(...) in PyTorch = np.tile (tiles the whole block).

np.repeat(...) = torch.repeat_interleave (repeats elements in place).

Same word, opposite meanings across the two libraries. This one bites everyone.

5 · Decision guide

  1. Need a brand-new axis? (e.g. batch N equal-shaped tensors) → stack.
  2. Growing an axis that exists? (longer sequence, more rows/cols) → concat/cat. Rows → axis=0/vstack; cols → axis=1/hstack.
  3. Just need (N,) → (1,N) or (N,1)? → add an axis: unsqueeze/expand_dims/[None].
  4. Stray size-1 axis after an op? → squeeze.
  5. Duplicate data to match shapes? → expand/broadcast_to (free view) or repeat/tile (copies).

6 · Interview traps

  • cat vs stack. cat two (3,) → (6,). stack them → (2,3). Rank is the tell.
  • unsqueeze is PyTorch-only. NumPy has no unsqueeze — use expand_dims or [None].
  • .T on a 1-D array is a no-op. To get a column, add an axis (a[:, None]), don't transpose.
  • hstack on 1-D joins along axis 0 (longer 1-D), not a new column. Want columns from 1-D? column_stack.
  • First arg is a list. np.stack([a, b]), not np.stack(a, b). Same for cat/concatenate.
  • expand/broadcast_to return views (no copy — don't write into them blindly). repeat/tile allocate real memory.

7 · Quick self-check

a is (4,), b is (4,). What is np.stack([a, b], axis=1).shape?

(4, 2). stack adds a new axis; putting it at position 1 makes each of the 4 positions hold a pair → columns.

x and y are both (2, 3). What is torch.cat([x, y], dim=0).shape?

(4, 3). Existing axis 0 grows from 2+2; the other axis must match (both 3) and stays put.

You have an embedding v of shape (128,). Make it a batch of one, (1, 128).

v[None] · v.unsqueeze(0) (torch) · np.expand_dims(v, 0) (numpy) · v.reshape(1, -1).

Linear regression: fold a bias column of ones into X of shape (n, d) → (n, d+1).

You're growing an existing axis (the columns), so it's a concat along axis 1. Cleanest: np.column_stack([X, np.ones(n)]) — it promotes the 1-D ones to a column for you. Equivalents: np.hstack([X, np.ones((n, 1))]) or np.concatenate([X, np.ones((n, 1))], axis=1). (This is the bug from the original session: unsqueeze doesn't exist in NumPy.)
