The LLD Cheat Sheet

Added 2026-08-24 · Machine-coding rounds for ML/platform roles

The one-line diagnosis: interviewers score what they see on screen, not what you know. A staff-level verbal answer next to an empty class scores as mid-level. Everything below converts knowledge you already have into the format that scores.

3 · Nine moments: mid-level vs staff

Real code and real spoken responses for the moments that decide the round. Every ❌ below is an actual pattern interviewers report — several are verbatim from a real mock session.

Moment 1 — The opening (minute 0)
✗ Mid

“Do you want me to implement the entire gateway module?”

…or worse: silence, then coding.

Vague scope question → vague answer → discovers real scope at minute 30. Zero clarifying questions is failure mode #8.
✓ Staff

“Three questions before I start. One — do clients name a model, and can one model be served by multiple providers? Two — what does failure look like: 429s, timeouts, 5xx, all of the above? Three — single process for this exercise, or do replicas share state?”

Then the lock: “So the core is unified routing with fallback and retries; streaming and auth are out of scope; done = a running demo of fallback. Correct?”

3 sharp questions + a scope restatement. ~90 seconds, and the scoping dimension is already banked.

class ProviderAdapter(ABC):
    @abstractmethod
    async def complete(self, req: LLMRequest) -> LLMResponse: ...
    # unified <-> provider format translation lives INSIDE the adapter

ADAPTERS: dict[str, type[ProviderAdapter]] = {}
def register(name):

    return deco

@register("anthropic")

Moment 5 — Failure handling (the taxonomy)
✗ Mid 
if response.is_successful():
    return response
# else: try next provider   (429 == timeout == 500 == 401)

“If it fails we just go to the next provider.”

All failures collapsed into one policy. A 401 will burn every provider in the cascade; a 429’d provider gets hammered again by the very next request.
✓ Staff 
class RateLimited(GatewayError):    ...  # 429 -> cooldown provider, fallback NOW
class ProviderTimeout(GatewayError): ... # -> retry w/ backoff within budget
class ProviderDown(GatewayError):   ...  # 5xx -> retry once, then fallback
class AuthError(GatewayError):      ...  # 401 -> fail fast, NEVER retry
class BadRequest(GatewayError):     ...  # 400 -> client bug: no retry, no fallback

“These failures have different policies — let me write the taxonomy before the retry logic.”

Six lines of code, and the robustness dimension flips from 2 to 3+. Taxonomy in the adapter, policy in the router.
Moment 6 — Retries (the staff separator)
✗ Mid 
backoffs = [10, 20]        # fixed, no jitter
client = OpenAI()          # SDK default: retries internally too
Gateway retries 3× while the SDK retries 4× underneath = (1+2)×(1+3) = 12 calls per request during an outage — a retry storm you built yourself. Fixed backoffs with no jitter synchronize thundering herds. This exact issue is the most commonly fed-and-dropped probe.
✓ Staff 
client = OpenAI(max_retries=0)   # LiteLLM does exactly this

async def with_retry(fn, attempts=3, base=0.5, deadline=None):
    for i in range(attempts):
        try:
            return await fn()
        except (ProviderTimeout, ProviderDown):
            if i == attempts - 1 or (deadline and deadline.exceeded()):
                raise
            await asyncio.sleep(base * 2**i + random.uniform(0, base))
        except RateLimited:
            raise   # no retry — cooldown + fallback is the router's job

“I pin SDK retries to zero so retries live at exactly one layer — otherwise router retries times SDK retries compound.”

One sentence + one kwarg. This is the named staff-vs-senior separator on gateway questions.

✓ Staff 
def admit(self, key, req) -> bool:
    est = est_prompt_tokens(req) + req.max_tokens     # admit on ESTIMATE
    return self.window(key).used + est <= self.limit(key)

def reconcile(self, key, usage):                      # after generation
    self.window(key).add(usage.input + usage.output)  # overage -> next req blocked

“Restating: token limits per key, output unknown at admission. So — admit on estimate, reconcile after, eat bounded overage. That slots in at the gateway entry, one class and one call site. Coding it now.”

The twist-absorption script: restate → locate the seam → insertion plan → minimal code. The estimate-then-reconcile shape answers every “cost unknown at admission” twist.
Moment 8 — Async discipline
✗ Mid 
asyncio.sleep(backoff)            # no await: never sleeps

response.is_successful()          # AttributeError: coroutine has no ...
Mixed sync/async is worse than either. These three tells each say “hasn’t actually run async code.”
✓ Staff 
async def handle(self, req):                  # async end-to-end
    async with asyncio.timeout(self.request_budget):   # per-REQUEST deadline
        return await self._route(req)

# demo concurrency in main():
results = await asyncio.gather(gw.handle(r1), gw.handle(r2))

“Gateways are I/O-bound, so async end-to-end. Two requests to the same key at the same instant — check-and-increment must be atomic. In one process that’s fine; across replicas it’s a Redis Lua script, or accept small overshoot and reconcile.”

Commit fully or exempt yourself out loud (“sync for demo clarity; prod is async because…”). Naming the race before the interviewer does banks the concurrency score.
Moment 9 — Code review answers (last 5 minutes)
✗ Mid

“The providers have a lot of vagaries… timeouts and stuff like that… a lot of work needs to go into that.”

“How would I test it? I’d add unit tests.”

Hand-waves. The last five minutes are fresh in the interviewer’s memory when they write the scorecard — vagueness here taxes everything before it.
✓ Staff

Walkthrough (data flow, not class list): “A request enters at the facade → limiter admits on estimate → router picks by priority among healthy deployments → adapter translates → retry wraps the call → reconcile usage → log.”

Testing: “The scripted fakes are the harness — each policy is one script: ["429","ok"] proves cooldown-plus-fallback.”

Breaks under load: “The limiter dict — single-process bottleneck and a data race. p99 admission latency and overshoot rate expose it; Redis with a Lua check-and-increment fixes it.”

Formats: flow-walkthrough, script-as-test, bottleneck + metric + fix. Specific beats comprehensive.

4 · The pattern toolbox (6 shapes, ~15 lines each)

1 · Adapter ABC + registry

THE extensibility answer (Moment 3 above). Add a backend = subclass + register line. LiteLLM’s provider map; TrueFoundry Cognita’s BaseVectorDB.

class ProviderAdapter(ABC):
    @abstractmethod
    async def complete(self, req: LLMRequest) -> LLMResponse: ...

ADAPTERS: dict[str, type[ProviderAdapter]] = {}
def register(name):
    def deco(cls): ADAPTERS[name] = cls; return cls
    return deco
2 · Dataclass boundaries + Enum states 
class Status(Enum):
    OK = "ok"; RATE_LIMITED = "rate_limited"; TIMEOUT = "timeout"; ERROR = "error"

@dataclass(frozen=True)
class LLMRequest:  api_key: str; model: str; prompt: str; max_tokens: int = 512
@dataclass
class LLMResponse: status: Status; text: str | None; provider: str | None; usage: "Usage | None"

Unified request/response at every seam. Frozen = requests can’t mutate mid-flight.

3 · Error taxonomy as code

4 · Retry at exactly ONE layer 
client = SDK(max_retries=0)          # pin the inner layer to zero

await asyncio.sleep(base * 2**i + random.uniform(0, base))  # backoff + JITTER

Say it: “otherwise gateway retries × SDK retries compound — 3×4 = 12 calls.”

5 · Circuit breaker per deployment 
@dataclass
class Breaker:                 # closed -> open -> half-open
    fails: int = 0
    opened_at: float = 0.0
    cooldown: float = 30.0
    def available(self, now):
        return self.opened_at == 0 or now - self.opened_at > self.cooldown
    def record(self, ok, now, was_429=False):
        self.fails = 0 if ok else self.fails + 1
        if was_429 or self.fails >= 3:
            self.opened_at = now

A 429’d provider must not be retried by the very next request. Breakers live per deployment (provider+model), not globally.

6 · Estimate-then-reconcile 
def admit(self, key, req):
    est = est_prompt_tokens(req) + req.max_tokens
    return self.window(key).used + est <= self.limit(key)

def reconcile(self, key, usage):
    self.window(key).add(usage.input + usage.output)

The answer whenever cost is unknown at admission — output tokens, job duration. Naive pre-check = mid-level; reconcile = staff.

Bonus seam — the middleware chain. Structure the gateway as auth → rate-limit → cache → route → call → log and every twist (“add semantic caching”, “add audit logs”) becomes ONE insertion. Even just saying this pipeline exists scores.

5 · The error → policy map

FailureRetry?Policy
401 authneverFail fast. Retrying auth errors burns the cascade for nothing.
400 bad requestneverClient bug — no retry, no fallback either.
429 rate limitednot hereCooldown that provider (breaker opens) + fall back immediately.
TimeoutyesBackoff + jitter, inside the per-request latency budget.
5xx provider downonceRetry once, then fall back; repeated 5xx trips the breaker.

Worst-case latency = attempts × providers × timeout — so the retry budget hangs off a per-request deadline, not per-call sleeps.

7 · The 10 interviewer-reported killers

  1. 15 classes in 30 minutes — “KISS is the most violated principle”
  2. God class doing translation + routing + retries + limits
  3. No running code / no main() — the most common verdict-flipper
  4. Rigid at the twist — insertion shouldn’t require rewriting the core
  5. Pattern forcing — every pattern needs a “because”
  6. Happy path only
  7. Polishing one class while the core is unimplemented
  8. Zero clarifying questions
  9. Silent coding stretches >3–5 min
  10. Hardcoded config with no “comes from config” narration
