1 · The one rule of matmul: shapes

(m×n) @ (n×p)  →  (m×p)   inner dims must match — they “cancel”

Read any product left to right: the columns of the left matrix must equal the rows of the right. Those two inner numbers annihilate; the outer two survive as the result’s shape. If the inner numbers differ, the product simply doesn’t exist.

2 · What each entry actually is

Entry C[i,j] is the dot product of row i of A with column j of B. That’s all matmul is: every output cell is one dot product. Step through it:

Why the shape rule exists is now obvious: a dot product needs both vectors the same length — row of A has n entries, column of B has n entries. The inner dims aren’t “cancelling” by magic; they’re the two ends of a dot product.

3 · The three laws

Not commutative: AB ≠ BA

Usually the shapes don’t even allow both. And when they do (square matrices), the results differ. Watch what one swap matrix does from each side:

1234 0110 = 2143  ← B on the right swaps columns
0110 1234 = 3412  ← B on the left swaps rows

Associative: (AB)C = A(BC) — the absorption trick

You may regroup a chain any way you like; the result is bit-for-bit identical. But the cost is wildly different, and that asymmetry is the entire MLA absorption trick: fold WqWUK together offline, so at decode time you never re-expand the cache.

Distributive: A(B + C) = AB + AC

Products distribute over sums from either side: (B + C)A = BA + CA too. This is why LoRA works at inference: x(W + BA) = xW + xBA — you can keep the adapter separate or merge it into W, identical outputs.

4 · Transpose toolkit

(Aᵀ)ᵀ = A
(A + B)ᵀ = Aᵀ + Bᵀ   and scalars pass through: (cA)ᵀ = cAᵀ
(AB)ᵀ = BᵀAᵀ   ORDER FLIPS · chains too: (ABC)ᵀ = CᵀBᵀAᵀ

The flip is forced by shapes: if A is m×n and B is n×p, then (AB)ᵀ is p×m — and the only way to build a p×m product from the transposes is Bᵀ (p×n) times Aᵀ (n×m). AᵀBᵀ doesn’t even chain.

Numeric check: (AB)ᵀ = BᵀAᵀ (and AᵀBᵀ fails)
AB = 2143  so  (AB)ᵀ = 2413
BᵀAᵀ = 0110 1324 = 2413  ✓ match
AᵀBᵀ = 1324 0110 = 3142  ✗ wrong order, wrong answer

(Using A = [[1,2],[3,4]], B = [[0,1],[1,0]] from §3.)

Mnemonic — socks and shoes. To undo “socks then shoes,” you remove shoes first. Transpose (and inverse) of a product unwind in reverse order: (AB)ᵀ = BᵀAᵀ, (AB)⁻¹ = B⁻¹A⁻¹.

5 · Vectors & dot products

Convention in papers: a vector x ∈ ℝd is a column (d×1). So xᵀ is a row (1×d), and:

q · k  =  qᵀk   (1×d)@(d×1) → (1×1) — a scalar
qᵀk = kᵀq   a scalar is its own transpose: (qᵀk)ᵀ = kᵀq
q kᵀ   (d×1)@(1×d) → (d×d) — OUTER product, a rank-1 matrix. Order changes everything.
‖q‖² = qᵀq   length squared is a dot with yourself

Example with q = (1, 2, 3), k = (4, 5, 6): qᵀk = 1·4 + 2·5 + 3·6 = 32 — one number. But q kᵀ is the full 3×3 “times table” of the entries, and its rank is 1.

Why this matters for attention. An attention logit is exactly qᵀk. Because a scalar equals its own transpose, qᵀ(W_UK c) = (qᵀW_UK) c = (W_UKᵀq)ᵀ c — all the same number, just regrouped or rewritten. Papers hop between these forms freely; now you can too.

6 · Rotations & RoPE

RᵀR = I   rotations are orthogonal, so R⁻¹ = Rᵀ
(Ra)·(Rb) = a·b   rotating BOTH vectors preserves dot products & norms
(Rmq)ᵀ(Rnk) = qᵀRmᵀRnk = qᵀRn−mk   only RELATIVE position survives

RoPE rotates q by its position m and k by its position n (each 2-D pair of channels by angle mω). The logit then depends only on n − m. Slide the positions and watch the dot product:

Widget · RoPE — the dot product only sees n − m
q at position m = 0 k at position n = 3 n − m = 3 q·k = 0.500

That’s the whole reason RoPE encodes relative position: shifting the entire sequence rotates every q and k by the same extra angle, and rotations applied to both sides of a dot product cancel (RᵀR = I).

Why Rm can’t be absorbed like WUK. Absorption folds two fixed matrices into one, offline, using associativity. But Rm depends on the token’s position m — it’s a different matrix for every position, known only at runtime. There is no single static matrix to fold into the weights. (This is exactly why MLA’s decoupled RoPE keys exist: the rotated part is kept separate; the position-free part gets absorbed.)

Inverses (for completeness)

(AB)−1 = B−1A−1   order flips, like transpose · needs square + full rank

Rarely computed explicitly in DL — but the socks-and-shoes flip shows up in derivations, and “R⁻¹ = Rᵀ” is the cheap special case you actually use.

    8 · Notation decoder — reading papers

    The symbols that carry 95% of the algebra in ML papers. Skim now, return whenever a paper throws glyphs at you.

    The #1 gotcha: column-math vs row-code.
    Papers (math convention): vectors are columns; a layer is y = Wx with W ∈ ℝout×in; chains apply right to left (W₂W₁x = first W₁, then W₂).
    Code (row convention): each row of a batch is an example; a layer is Y = XW with W ∈ ℝin×out; chains read left to right. Everything is the transpose of the paper: (Wx)ᵀ = xᵀWᵀ.
    PyTorch’s nn.Linear stores weight as (out, in) and computes x Wᵀ + b. When paper shapes and code shapes disagree, this convention flip is almost always why.

    The two rules doing the most work in MLA / RoPE algebra:
    1. Associativity — you choose where to put the parentheses; absorption is just choosing them offline.
    2. Rt depends on t — a position-dependent rotation is not one static matrix, so it can never be folded into fixed weights.
