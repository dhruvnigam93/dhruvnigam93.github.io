Four ML Classics from Scratch

Added 2026-08-27 · the tricks, why they work, how to remember — with demos

Linear regression, logistic regression, k-means, KNN. The four you get asked to code from scratch. This is the cheat sheet: the one trick per algorithm, the reason it works, the mnemonic, and the gotchas — plus a widget for each so the idea sticks.

The map: two families

Everything here splits into two ideas. Get this and the rest hangs off it.

1 · Fit-then-predict (parametric). Learn weights w, b by walking downhill on a loss with gradient descent. Training is the work; prediction is a cheap dot product. → Linear & Logistic regression.

2 · Geometry / distance. No weights — just distances between points. → KNN (memorize the data, let neighbors vote) and K-means (move cluster centers to the mean, repeat).

Cross-cut: KNN and logistic are supervised (labels). K-means is unsupervised (no labels — it invents the groups). Linear/logistic/KNN predict; k-means clusters.

The one gradient that covers two of them

If you remember a single equation from this page, make it this. Linear and logistic regression have the same gradient shape:

error = prediction - target        # the "residual" / error signal
dw    = (1/n) * X.T @ error         # error, weighted by each input, averaged
db    = (1/n) * error.sum()
why it works

Gradient descent asks: "nudge each weight which way to shrink the loss?" For both losses the answer collapses to the same thing — the error times the input. A feature that was large and pushed the prediction the wrong way gets the biggest correction. That's it.

remember

"Residual · input, averaged." The only difference: linear regression carries a factor of 2 (from the squared loss); logistic does not (the sigmoid and log-loss derivatives cancel — see below). Fold the 2 into the learning rate and even that difference vanishes.

1 · Linear regression

Model ŷ = Xw + b. Loss = mean squared error, MSE = mean((ŷ - y)²).

the trick

Two ways to solve it. Gradient descent: dw = (2/n)·Xᵀ(ŷ−y), db = (2/n)·Σ(ŷ−y). Closed form (normal equation): fold the bias in with a column of ones, then w = (XᵀX)⁻¹Xᵀy — exact, no iteration.

why it works

MSE is a convex bowl in (w, b) — one global minimum, no traps. The gradient points uphill, so stepping the opposite way always descends. The closed form is just "set the gradient to zero and solve" — possible only because the bowl is quadratic.

remember

Normal equation ≈ "X-transpose-X inverse, X-transpose-y." Say it as a chant. GD ≈ the shared "residual · input, averaged."

gotchas

① Use 2/n (mean, not sum) — a raw sum makes the given learning rate effectively n× too big and it diverges. ② Standardize features so one big-scale column doesn't dominate and one learning rate fits all. ③ Closed form needs XᵀX invertible — if features are collinear, use np.linalg.lstsq / pinv.

2 · Logistic regression

Model p = sigmoid(Xw + b), where sigmoid(z) = 1/(1+e⁻ᶻ). Loss = binary cross-entropy, BCE = −mean(y·log p + (1−y)·log(1−p)).

the trick

Take a linear score and squash it through a sigmoid into a probability. The payoff: dL/dz = p − y exactly, so the weight gradient is identical in shape to linear regression — dw = Xᵀ(p−y)/n. Learn one gradient, get two algorithms.

why the sigmoid derivative vanishes

The chain rule multiplies two pieces: sigmoid'(z) = p(1−p) and the BCE derivative ∂L/∂p = (p−y)/(p(1−p)). The p(1−p) cancels, leaving a clean p − y. This pairing of sigmoid + log-loss is designed to make optimization simple and convex.

remember

"Linear score → sigmoid → probability; gradient is still (p − y)·x." Sigmoid turns log-odds into a probability; the log-loss is its natural partner.

gotchas

① Stable sigmoid: exp(−z) overflows for very negative z — clip z to [−100,100] or branch on its sign. ② Clip p away from 0/1 before log (else log(0) = −inf). ③ Don't L2-regularize the bias — it encodes the base rate log(pos/neg); shrinking it skews every prediction. ④ The L2 term adds +λw to dw; flip that sign and the weights blow up. ⑤ No closed form — GD or Newton only.

Feel the squash. Drag the logit; watch it map to a probability.

The slope p(1−p) is biggest at z=0 (max uncertainty, p=0.5) and near-zero at the tails — that's why confident points barely move the weights, and why the sigmoid derivative shows up (then cancels) in the gradient.

3 · K-means

Unsupervised. Split data into k clusters minimizing inertia = Σ ‖x − centroid(x)‖² (total squared distance to each point's own center).

the trick — Lloyd's algorithm

Alternate two cheap half-steps until nothing changes:

# ASSIGN: each point -> nearest centroid
d = ((X[:,None,:] - C[None,:,:])**2).sum(-1)   # (n,k)
labels = d.argmin(1)
# UPDATE: each centroid -> mean of its members
for j in range(k):
    if (labels==j).any():
        C[j] = X[labels==j].mean(0)
why it converges

Each half-step can only lower inertia: assign sends every point to its closest center (shrinks its term), and update moves each center to its members' mean — and the mean is exactly the point that minimizes summed squared distance. Monotonically decreasing + bounded below ⇒ it converges. To a local min, not necessarily the global one.

remember

"Assign, Average, Repeat" (A-A-R). It's EM-lite: guess groups, recompute centers, re-guess.

gotchas

① Empty cluster → mean of nothing = NaN. Guard it (skip, or reseed that centroid to the farthest point). ② Local minima → run several random restarts, keep the lowest inertia; seed with k-means++. ③ Labels are permutation-invariant — compare the partition, not raw ids. ④ You must choose k (elbow on inertia, silhouette). ⑤ Euclidean ⇒ standardize features.

vectorize the update

Drop the k-loop with a scatter-add: sums = np.zeros((k,d)); np.add.at(sums, labels, X) then divide by np.bincount(labels, minlength=k). In PyTorch it's sums.index_add_(0, labels, X) — one atomic-add kernel instead of k masked reductions.

4 · K-nearest neighbors

Supervised, and lazy: there is no training. Store the data; at query time find the k closest points and let them vote (classification) or average (regression).

the trick 
d = pairwise_sq_dists(X_query, X_train)   # (nq, nt)
nn = np.argpartition(d, k, axis=1)[:, :k] # k nearest indices
preds = [np.bincount(y[row]).argmax()     # majority vote per row
         for row in nn]
why it works

Pure local smoothness: things close together tend to share a label (or value). No global model, no assumptions about the shape of the boundary — the boundary is whatever the data draws.

remember

"No fit. Ask the k closest to vote." All the cost is at query time: O(n·d) per query.

the two follow-up tricks interviewers want

① Memory-efficient distances. The naive (nq, nt, d) broadcast OOMs. Use the identity ‖a−b‖² = ‖a‖² + ‖b‖² − 2·a·b → a2[:,None] + b2[None,:] − 2·A@Bᵀ, memory O(nq·nt), not ×d. Clip tiny negatives before sqrt. ② argpartition, not argsort. You need the k-nearest set, not sorted — O(n) beats O(n log n).

gotchas

① np.bincount is 1-D only — loop the rows (k is tiny) and pass minlength=C. ② Ties: argmax returns the first max ⇒ smallest class id wins; use odd k for binary. ③ Standardize — distance is scale-sensitive. ④ Curse of dimensionality: in high d all points look equidistant and KNN degrades. ⑤ small k = noisy/overfit; big k = washes out local structure. ⑥ Scale it with KD-/ball-trees (low d) or approximate NN (FAISS/HNSW).
