0. The bugs you actually hit (fix these reflexes)

These are yours, from the drill. Each is a one-line reflex to internalize.

lr = Config.epochs — you passed 8 as the learning rate → the model diverged, 46% acc. Reflex: read from the instance cfg.lr, never the class Config. And an LR of 8 is absurd — from-scratch transformers live at 1e-3 … 3e-4.
torch.max(logits).index — torch.max(x) with no dim returns the global max scalar; .index isn't a thing. Reflex for predictions: preds = logits.argmax(dim=-1) → shape [B].
nn.Sequential([...]) — takes *args, not a list, and auto-chains. When you hand-loop with residuals/masks you want nn.ModuleList([...]). (§4)
nn.LayerNorm() — needs normalized_shape: nn.LayerNorm(d_model).
x_in += layer(x) — two bugs: you fed raw token IDs x instead of the embedded x_in, and TransformerEncoderLayer already adds its own residual, so += double-counts. Just x_in = layer(x_in).
silent training — you printed nothing, so a diverging loss was invisible. Always print per-epoch loss; it turns "why is acc bad?" into a 5-second diagnosis.
missing model.train()/eval() — matters the moment you have dropout (§1).

1. Dropout — what, where, why

What: during training only, randomly zero each activation with probability p, then scale the survivors by 1/(1-p) ("inverted dropout") so the expected sum is unchanged. At eval it's the identity (nothing dropped, no scaling). That scaling is exactly why you don't touch anything at test time.

Why: stops neurons co-adapting; approximates averaging an ensemble of sub-networks → regularization. It's a lever you pull when train acc ≫ val acc.

Where to put it (transformer):
  • on the sum of token + positional embeddings,
  • on the attention probabilities (after softmax),
  • on each sub-layer output before the residual add (residual dropout),
  • inside the FFN, after the activation.
Not on the final logits. Typical p: 0.1 for LLMs, up to 0.3–0.5 in small MLPs.
The trap: nn.Dropout respects model.train()/eval() automatically. F.dropout(x) does not unless you pass training=self.training. Prefer the module. And if you forget model.eval(), dropout stays on at inference → noisy, worse predictions (one of your minor misses).

2. The canonical training + eval loop

Memorize this shape. The three lines that must be in this order per step: zero_grad → backward → step.

model.train()
opt = torch.optim.AdamW(model.parameters(), lr=cfg.lr, weight_decay=0.01)

for epoch in range(cfg.epochs):
    running = 0.0
    for xb, yb in train_loader:
        xb, yb = xb.to(device), yb.to(device)

        logits = model(xb)                     # forward
        loss   = F.cross_entropy(logits, yb)   # raw logits + int targets

        opt.zero_grad()                        # clear old grads (they accumulate!)
        loss.backward()                        # compute new grads
        # torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # optional, stabilizes
        opt.step()                             # update weights

        running += loss.item() * xb.size(0)
    print(f"epoch {epoch}: loss {running/len(train_loader.dataset):.4f}")   # SEE the loss
@torch.no_grad()                # no autograd graph -> faster, less memory
def evaluate(model, loader, device):
    model.eval()                # turn OFF dropout / use running BN stats
    correct = total = 0
    for xb, yb in loader:
        xb, yb = xb.to(device), yb.to(device)
        preds = model(xb).argmax(dim=-1)      # NOT torch.max(...).index
        correct += (preds == yb).sum().item()
        total   += yb.size(0)
    return correct / total
Why zero_grad at all? PyTorch accumulates grads into .grad on every backward(). Skip zeroing and you sum this step's grads onto last step's → garbage updates. (Accumulation is a feature — it's how you fake a big batch across micro-batches.)
Numbers to know: AdamW lr ≈ 3e-4 (transformers) to 1e-3 (small models); weight_decay ≈ 0.01–0.1; real training uses warmup + cosine decay. cross_entropy wants raw logits (it does log_softmax inside) and integer class targets — never softmax before it.

3. nn.Module vs torch.nn.functional

Same math, different packaging. The rule is about state.

Use the Module (nn.X) when the op owns parameters or has train/eval-dependent behavior: nn.Linear, nn.Conv2d, nn.LayerNorm, nn.Embedding, nn.Dropout, nn.BatchNorm2d, nn.MultiheadAttention. Create in __init__ so params register + move with .to(device).
Use functional (F.x) for stateless ops: F.relu, F.gelu, F.softmax, F.cross_entropy, F.scaled_dot_product_attention, F.normalize. Fine to call directly in forward.
The classic bug: F.dropout(x) and F.batch_norm(...) ignore model.train()/eval() unless you thread the flag through yourself. Stateful op → reach for the Module. Activations like ReLU/GELU have no state, so either form is fine (module version is handy inside nn.Sequential).

4. ModuleList vs Sequential vs ModuleDict

ContainerHas its own forward?Use when
nn.Sequential(*mods)Yes — calls them in order Simple linear pipeline, no custom logic. Takes *args, not a list.
nn.ModuleList([...])No — you loop over it You need custom flow between layers: residuals, passing a mask, cross-attention, early exit. What transformer stacks use.
nn.ModuleDict({...})No Named/branchy submodules you index by key.
Never use a plain Python list of modules — its params don't register, so they won't train and won't .to(device). Always wrap in ModuleList/Sequential. 
# Sequential: it runs the chain for you
mlp = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d))
y = mlp(x)

# ModuleList: YOU write the forward (needed for residuals / masks)
self.blocks = nn.ModuleList([Block(cfg) for _ in range(n)])
for blk in self.blocks:
    x = blk(x, mask)          # <- custom args between layers

5. Canonical attention (from scratch)

The equation: Attention(Q,K,V) = softmax(QKᵀ / √d_k) · V. The √d_k keeps score variance ~1 so softmax doesn't saturate into one-hot at large d.

class MultiHeadSelfAttention(nn.Module):
    def __init__(self, d_model, nhead, dropout=0.0):
        super().__init__()
        assert d_model % nhead == 0
        self.h, self.dh = nhead, d_model // nhead
        self.qkv  = nn.Linear(d_model, 3 * d_model)
        self.proj = nn.Linear(d_model, d_model)
        self.drop = nn.Dropout(dropout)

    def forward(self, x, mask=None):            # x: [B, T, D]
        B, T, D = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)  # each [B, T, D]
        # [B,T,D] -> [B,h,T,dh]
        split = lambda t: t.view(B, T, self.h, self.dh).transpose(1, 2)
        q, k, v = split(q), split(k), split(v)

        att = (q @ k.transpose(-2, -1)) / self.dh**0.5   # [B,h,T,T]
        if mask is not None:
            att = att.masked_fill(mask == 0, float('-inf'))
        att = self.drop(att.softmax(dim=-1))
        out = att @ v                             # [B,h,T,dh]
        out = out.transpose(1, 2).contiguous().view(B, T, D)  # back to [B,T,D]
        return self.proj(out)
In real code, prefer the fused kernel: F.scaled_dot_product_attention(q, k, v, is_causal=True, dropout_p=p) — that's FlashAttention under the hood (faster, less memory). Say this in the interview; then show you can still hand-roll it.

6. Positional embeddings

Attention is permutation-invariant — with no position signal, "dog bites man" = "man bites dog". So we inject position. Four flavors worth naming:

TypeHowNotes / who uses it
Learned absolutenn.Embedding(max_len, d), added to token emb Simplest (what your classifier would use). Capped at max_len, no extrapolation. BERT, GPT-2, ViT.
Sinusoidalfixed sin/cos at geometric frequencies No params, extrapolates a bit. Original "Attention Is All You Need".
RoPE (rotary)rotate q,k by a position-dependent angle inside attention Encodes relative position, great long-context extrapolation. LLaMA, Qwen → so Nanonets' Qwen2.5-VL base.
ALiBiadd a linear distance penalty to attention scores No embedding at all; cheap length extrapolation.
Say this: modern LLMs mostly moved from added absolute embeddings to RoPE, because relative position generalizes to longer sequences than trained on. Sinusoidal is the thing to be able to sketch.

7. LayerNorm vs RMSNorm vs BatchNorm

Normalizes overFormula (per token)Where
LayerNormfeature dim, per sample (x−μ)/√(σ²+ε)·γ + βTransformers. Batch-independent → good for variable length.
RMSNormfeature dim, per sample x/√(mean(x²)+ε)·γ — no mean-subtraction, no β Cheaper, works as well. LLaMA, Qwen, most modern LLMs.
BatchNormbatch dim, per feature uses batch mean/var; running stats at eval CNNs. Bad for transformers / small batch / variable length.
RMSNorm in 4 lines (know why it's cheaper: drops the mean and the bias): 
class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__(); self.g = nn.Parameter(torch.ones(d)); self.eps = eps
    def forward(self, x):
        rms = x.pow(2).mean(-1, keepdim=True).add(self.eps).rsqrt()
        return x * rms * self.g
Pre-norm vs post-norm: pre-norm (norm_first=True, norm inside the residual branch) trains deep stacks stably — the modern default, and what you set. Original post-norm needs LR warmup or it diverges.

8. PyTorch transformer classes — who's who

The names trip people up. Layer = one block; the un-suffixed class = a stack of them.

ClassWhat it is
nn.MultiheadAttentionJust the attention op (with in/out projections).
nn.TransformerEncoderLayerOne encoder block: self-attn + FFN + 2 norms + residuals. (what you used)
nn.TransformerEncoderA stack of N encoder layers. You could've passed this one layer + num_layers instead of a ModuleList.
nn.TransformerDecoderLayerOne decoder block: masked self-attn + cross-attn (over encoder output) + FFN.
nn.TransformerDecoderA stack of decoder layers.
nn.TransformerFull encoder→decoder (seq2seq, e.g. translation).
Encoder layer vs decoder layer — the two differences:
  1. Decoder self-attn is causally masked (can't peek ahead); encoder is bidirectional.
  2. Decoder has an extra cross-attention where Q comes from the decoder and K,V from the encoder's output ("memory"). Encoder has none.
Which architecture for what:
  • Encoder-only (BERT, ViT) → understanding / classification / embeddings. Your document classifier is here — correct choice.
  • Decoder-only (GPT, LLaMA, Qwen) → generation.
  • Encoder–decoder (T5, original Transformer) → seq2seq (translate, summarize).

9. Assemble a full transformer (encoder + decoder)

One reusable attention module powers all three attention types — just pass q,k,v separately: self-attn is (x,x,x), cross-attn is (decoder, memory, memory).

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, nhead, dropout=0.1):
        super().__init__()
        assert d_model % nhead == 0
        self.h, self.dh = nhead, d_model // nhead
        self.wq = nn.Linear(d_model, d_model); self.wk = nn.Linear(d_model, d_model)
        self.wv = nn.Linear(d_model, d_model); self.wo = nn.Linear(d_model, d_model)
        self.drop = nn.Dropout(dropout)
    def forward(self, q, k, v, mask=None):          # q:[B,Tq,D]  k,v:[B,Tk,D]
        B, Tq, Tk = q.size(0), q.size(1), k.size(1)
        split = lambda x,T: x.view(B,T,self.h,self.dh).transpose(1,2)   # [B,h,T,dh]
        q,k,v = split(self.wq(q),Tq), split(self.wk(k),Tk), split(self.wv(v),Tk)
        s = (q @ k.transpose(-2,-1)) / self.dh**0.5                     # [B,h,Tq,Tk]
        if mask is not None: s = s.masked_fill(mask == 0, float('-inf'))
        o = self.drop(s.softmax(-1)) @ v                               # [B,h,Tq,dh]
        o = o.transpose(1,2).contiguous().view(B, Tq, self.h*self.dh)
        return self.wo(o)

Encoder layer vs decoder layer

The decoder block has the two things the encoder lacks: a causal self-attn and a cross-attn over the encoder's output.

class EncoderLayer(nn.Module):          # self-attn + FFN  (pre-norm)
    def forward(self, x, src_mask=None):
        h = self.n1(x); x = x + self.drop(self.attn(h, h, h, src_mask))
        x = x + self.drop(self.ff(self.n2(x)));  return x

class DecoderLayer(nn.Module):          # MASKED self-attn + CROSS-attn + FFN
    def forward(self, x, memory, tgt_mask=None, mem_mask=None):
        h = self.n1(x); x = x + self.drop(self.self_attn(h, h, h, tgt_mask))            # causal
        h = self.n2(x); x = x + self.drop(self.cross_attn(h, memory, memory, mem_mask)) # to encoder
        x = x + self.drop(self.ff(self.n3(x)));  return x

Stacks + the masks (where seq2seq gets fiddly)

class Encoder(nn.Module):               # emb*√d + pos -> N EncoderLayers -> norm
    def forward(self, src, src_mask=None):
        x = self.pos(self.emb(src) * self.scale)
        for l in self.layers: x = l(x, src_mask)
        return self.norm(x)

class Decoder(nn.Module):               # ... -> N DecoderLayers -> norm -> Linear(vocab)
    def forward(self, tgt, memory, tgt_mask=None, mem_mask=None):
        x = self.pos(self.emb(tgt) * self.scale)
        for l in self.layers: x = l(x, memory, tgt_mask, mem_mask)
        return self.out(self.norm(x))                       # logits [B,T,vocab]

def pad_mask(seq, pad=0):    # [B,T] -> [B,1,1,T]  True = NOT padding
    return (seq != pad).unsqueeze(1).unsqueeze(2)
def causal_mask(T, device): # [1,1,T,T] lower-triangular, True = allowed
    return torch.tril(torch.ones(T, T, device=device, dtype=torch.bool)).view(1,1,T,T)

# forward:
src_mask = pad_mask(src)                                    # encoder: pad only
tgt_mask = pad_mask(tgt) & causal_mask(tgt.size(1), tgt.device)   # decoder: pad AND causal
memory   = encoder(src, src_mask)
logits   = decoder(tgt, memory, tgt_mask, src_mask)        # cross-attn masks the source
Mask cheat: encoder self-attn = padding only (bidirectional); decoder self-attn = padding and causal (no peeking ahead); cross-attn masks the source padding (queries = target, keys = encoder memory). Also scale embeddings by √d_model (Vaswani), and this is pre-norm.
⚠ Built-in nn.Transformer flips the convention: there, True in attn_mask/key_padding_mask means block this (opposite of the hand-rolled True = keep), and you build the causal mask with nn.Transformer.generate_square_subsequent_mask(T). Mixing the two silently trains garbage.
Verified end-to-end: Transformer(src, tgt) → logits [B, Tt, tgt_vocab].

10. Images & VLMs — the vision crash course

Nanonets is a document-AI / VLM shop (their OCR is fine-tuned Qwen2.5-VL). You don't need to be a CV expert — you need to talk credibly and connect it to what you know. The bridge: a ViT turns an image into a sequence of tokens, then it's just the transformer you already built.

Image tensors & preprocessing (the concrete gotchas)
  • Layout is channels-first: [B, C, H, W] in PyTorch (not [B,H,W,C] like TF/NumPy). Mixing these up is the #1 image bug.
  • Preprocess: resize → to tensor (scales to [0,1]) → normalize with dataset mean/std. ImageNet: mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225].
  • Augment (train only): random crop/flip/color-jitter; for documents: rotation, blur, noise, but not horizontal flip (text would reverse).
from torchvision import transforms as T
tf = T.Compose([T.Resize((224,224)), T.ToTensor(),
                T.Normalize([0.485,0.456,0.406], [0.229,0.224,0.225])])
CNN basics (Conv2d, output size, ResNet)
  • nn.Conv2d(in_ch, out_ch, kernel, stride, padding) — slides a small filter; weight sharing gives translation invariance and few params.
  • Output size: out = (W − K + 2P)/S + 1. "same" padding when P=(K−1)/2, S=1.
  • ResNet = the workhorse backbone; residual connections let you train very deep nets (same idea as transformer residuals). BatchNorm lives here, not in transformers.
  • Pooling / stride shrink spatial size; channels grow with depth.
ViT — "an image is worth 16×16 words" (the bridge)
  1. Split the image into fixed patches (e.g. 16×16). Each patch is flattened + linearly projected → a patch embedding. Trick: that's literally a Conv2d(3, d, kernel=16, stride=16).
  2. You now have a sequence of patch tokens. Prepend a [CLS] token, add positional embeddings.
  3. Run a standard transformer encoder (the one you built). Classify from the [CLS] token (or mean-pool).

So your text classifier and a ViT are the same encoder — only the tokenizer differs (BPE tokens vs patch embeddings).

VLMs — how Nanonets' OCR-free extraction works
  1. Vision encoder (a ViT) turns the document image into visual tokens.
  2. A projector/adapter (small MLP) maps those into the LLM's text-embedding space.
  3. Visual tokens are concatenated with the text prompt ("extract the invoice fields as JSON") and fed to a decoder LLM (Qwen2.5), which generates the answer.

"OCR-free" = no separate text-detection+recognition pipeline; the model reads pixels and emits structured text end-to-end. Contrast with traditional OCR: detect text boxes → recognize each (CRNN + CTC loss) → post-process. Trade-off talking point: VLMs handle layout/tables/context far better but cost more compute and can hallucinate — hence confidence scores + human-in-the-loop.

Detection & the metrics to name-drop
  • Table / object detection: predict bounding boxes + classes. Models: DETR (transformer-based, set prediction + Hungarian matching), Faster R-CNN, YOLO.
  • IoU (intersection-over-union) measures box overlap; mAP (mean average precision) is the standard detection metric.
  • DocVQA is the benchmark for document-understanding VLMs (the one Nanonets quotes).
  • If asked "classify document images": fine-tune a pretrained ResNet/ViT (transfer learning) — don't train from scratch. Freeze the backbone, train the head first, then unfreeze.
If a vision question comes and you're unsure: anchor to what you know — "an image becomes a sequence of patch tokens, then it's the same transformer encoder; the differences are channels-first tensors, normalization stats, and using a pretrained backbone via transfer learning." That framing alone reads as competent.

11. CNN blocks — Conv / BatchNorm / Dropout in code

The canonical vision block is Conv → BN → ReLU. Conv gets bias=False because BatchNorm's β already adds a bias.

def conv_bn_relu(cin, cout, k=3, s=1, p=1):
    return nn.Sequential(
        nn.Conv2d(cin, cout, k, s, p, bias=False),   # bias=False: BN's beta subsumes it
        nn.BatchNorm2d(cout),
        nn.ReLU(inplace=True),
    )

ResNet basic block — the canonical residual conv assembly (project the skip when the shape changes):

class BasicBlock(nn.Module):
    def __init__(self, cin, cout, stride=1):
        super().__init__()
        self.conv1, self.bn1 = nn.Conv2d(cin,cout,3,stride,1,bias=False), nn.BatchNorm2d(cout)
        self.conv2, self.bn2 = nn.Conv2d(cout,cout,3,1,1,bias=False),     nn.BatchNorm2d(cout)
        self.short = nn.Sequential()
        if stride != 1 or cin != cout:               # skip must match shape
            self.short = nn.Sequential(nn.Conv2d(cin,cout,1,stride,bias=False), nn.BatchNorm2d(cout))
    def forward(self, x):
        out = F.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        return F.relu(out + self.short(x))           # residual, THEN activation

Small classifier — dropout lives in the head, not between conv+BN layers:

self.features = nn.Sequential(
    conv_bn_relu(3, 32),  nn.MaxPool2d(2),           # -> [B,32,16,16]
    conv_bn_relu(32, 64), nn.MaxPool2d(2),           # -> [B,64,8,8]
    conv_bn_relu(64,128), nn.AdaptiveAvgPool2d(1),   # -> [B,128,1,1]
)
self.head = nn.Sequential(nn.Flatten(), nn.Dropout(0.5), nn.Linear(128, num_classes))
ThingCanonical rule
OrderConv → BN → ReLU. Conv bias=False under BN.
BatchNorm statsNormalizes per-channel over (B,H,W) in train; uses running mean/var at eval → model.eval() is mandatory.
Conv output size(W − K + 2P)/S + 1; "same" when S=1, P=(K−1)/2.
Small batchesBN degrades → use GroupNorm/LayerNorm (why transformers avoid BN).
Dropout placementIn the classifier head. For conv maps use nn.Dropout2d (drops whole channels).
Interview line that ties §7 and §11 together: "BatchNorm normalizes across the batch per channel and keeps running stats for eval, so it's batch-size sensitive; transformers use LayerNorm because it's batch-independent and works with variable-length sequences."

12. Grab-bag they might probe

Overfitting vs underfitting — diagnose & fix

Train ≫ val (overfit): more data / augmentation → dropout → weight decay → early stopping → smaller model → label smoothing. Pull in that rough order.

Train also bad (underfit): bigger model, train longer, higher LR, less regularization, better features/tokenization, check the data pipeline.

Optimizer / schedule / precision
  • AdamW = Adam with decoupled weight decay (correct L2). Default for transformers.
  • Schedule: linear warmup then cosine decay. Warmup avoids early divergence.
  • Grad clipping: clip_grad_norm_(params, 1.0) to tame spikes.
  • Mixed precision: torch.autocast + GradScaler (fp16) or bf16 — ~2× faster, half the memory.
  • Grad accumulation: sum grads over k micro-batches, step once → simulate batch k× bigger.
Tensor reflexes (no-autocomplete survival kit)
  • Predicted class: logits.argmax(dim=-1).
  • Python number out of a 0-dim tensor: .item().
  • Detach from graph: .detach(); disable grad: with torch.no_grad(): / @torch.no_grad().
  • Reshape needs contiguous after transpose/permute: .contiguous().view(...) or just .reshape(...).
  • Move data and model to the same device; mismatch is a top runtime error.
  • cross_entropy: raw logits [B,C] + int targets [B]. Never pre-softmax.
  • Broadcasting: [B,1,T,T] masks broadcast over heads [B,h,T,T].
KV-cache & inference (Nanonets serves at scale — likely follow-up)

KV-cache: in autoregressive decoding, cache each step's K and V so you don't recompute attention over the whole prefix every token → O(T) not O(T²) per step. Applies to decoders, not your encoder classifier. Memory cost grows with sequence × layers × heads → the thing PagedAttention/vLLM manages.

Serving levers: quantization (INT8/FP16/bf16), continuous batching, ONNX/TensorRT export, distillation to a smaller model. Nanonets' pitch — a 3–4B model beating a 72B — is basically this: right-size + fine-tune + serve efficiently.
