Counting DP: Combinations vs Permutations

Added 2026-09-03 · one recursion, two knobs

The confusion this kills: "Is this #518 or #377? Do I loop coins or amount? Why is my count too big?" These aren't different algorithms. They're the same take/skip recursion — you only choose two things: does order count? and can a coin repeat?

1. The two knobs

Every "count the ways to reach a total" problem is fixed by two yes/no questions:

  • Order — is 1 + 2 the same as 2 + 1?
    Same → combinations.   Different → permutations.
  • Reuse — can you pick the same coin again?
    Yes → unbounded knapsack.   No → 0/1 knapsack.

Two bits → four problems. Flip both below and watch the template and the actual enumerated ways change.

3. Why order lives in the STATE

    
This is the whole lesson. If the state is just dp(remaining), then at remaining = 3 the call explores "take a 1, then make 2" and "take a 2, then make 1" — building 1+2 and 2+1 separately. With no memory of what you already committed to, you count permutations by default.

    
Add a coin index i to the state and "skip" advances to i+1 and never looks back — a smaller-index coin can never come after a larger one. That collapses 2+1 into 1+2: now you count combinations.

    

        Combinations vs permutations is a state-design decision, not a code tweak.

        Permutations → state = (remaining), every call tries all coins.

        Combinations → state = (i, remaining), skip advances i so order is frozen.
    


    
4. The bottom-up one-liner

    
Written iteratively, the two knobs become loop order and loop direction:

    
# dp[x] = ways to make total x,  dp[0] = 1

# COMBINATIONS (#518): coins on the OUTSIDE
for c in coins:
    for x in range(c, amount+1):     # forward = reuse
        dp[x] += dp[x - c]

# PERMUTATIONS (#377): amount on the OUTSIDE
for x in range(1, amount+1):
    for c in coins:
        dp[x] += dp[x - c]

    
Coins outer → combinations. Amount outer → permutations. For 0/1 (use once) in the combination form, run the inner amount loop backwards — range(amount, c-1, -1) — so each coin touches each cell once.

6. Carry these three lines

    
    
        
  • Order = state. Index in the state ⇒ combinations. Amount-only state ⇒ permutations.
    • 
        
  • Reuse = which index take recurses to. Stay at i ⇒ reuse; go to i+1 ⇒ once.
    • 
        
  • Bottom-up: coins-outer = combinations, amount-outer = permutations; backwards inner = 0/1.
