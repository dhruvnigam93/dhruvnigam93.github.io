DFS: One Skeleton, Three Shapes

Added 2026-09-01

DFS is really one skeleton with three canonical specializations. Knowing which one you're reaching for is half the battle.

The skeleton

def dfs(node):
    if base_case:              # None / out of bounds / already visited
        return base_value
    # ... work happens here, before and/or after the recursive calls ...
    results = [dfs(child) for child in children]
    return combine(node, results)

Everything below is this shape with the knobs set differently. Tap a question type to isolate the matching shape:

Shape 1

Bottom-up tree

Answer flows UP via return values. A node's answer depends on its children — subtree properties like height, diameter, "is balanced", max path sum, subtree sums. Optionally update a self.best on the side.

def dfs(node):
    if not node:                       # base case first, returns identity value
        return 0
    left = dfs(node.left)
    right = dfs(node.right)
    return 1 + max(left, right)        # combine child results at the parent
Shape 2

Top-down tree

State flows DOWN via parameters. A node's job depends on the path from the root, not its children — root-to-leaf path sum (#112), validate BST with (low, high) bounds (#98), depth tracking. Usually act/collect at the leaf.

def dfs(node, state):                  # state = path sum, (lo, hi) bounds, depth...
    if not node:
        return
    if is_leaf(node) and satisfies(state, node):
        self.result.append(...)        # collect at the leaf
    dfs(node.left,  update(state, node))
    dfs(node.right, update(state, node))
Shape 3

Graph / grid DFS

Same shape + a visited marker, set BEFORE recursing. When cycles are possible — number of islands (#200), flood fill, connected components, cycle detection. Critical bug: mark visited BEFORE the recursive calls, or you infinite-loop on a back-edge (the #207/#417/#133 lesson).

def dfs(r, c):
    if out_of_bounds(r, c) or (r, c) in visited or grid[r][c] != target:
        return
    visited.add((r, c))                # mark BEFORE recursing (or mutate grid in place)
    for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        dfs(r + dr, c + dc)

Two invariants
  1. Base case first — None / out-of-bounds / already-visited.
  2. On LeetCode, carry a global result with self.x or a one-element list, NOT nonlocal — LeetCode's python mode is Python 2, where nonlocal is a SyntaxError. Same trap: math.inf — use float('inf').
